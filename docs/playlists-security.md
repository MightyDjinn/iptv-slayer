# Playlists and security

UTF-8 extended M3U: `#EXTINF` supplies the name after the first comma outside double-quoted attributes; a following HTTP(S) URL supplies the stream. Bare URL lines get generated names. Other comments and attributes are ignored. HTTP(S) relative stream URLs resolve against the final playlist URL after redirects; local relative stream paths and non-HTTP(S) streams are ignored. HTTP requests time out after 20 seconds and allow up to five redirects. Browser-selected URL fetches only follow redirects within the same origin, preventing credentials from being sent elsewhere. No EPG, encrypted credentials vault, `#EXTVLCOPT`, or advanced M3U parsing is provided. An empty or unsupported playlist is rejected when selected in the browser.

## Playlist limits

Each playlist is limited to 10 MiB of UTF-8 input, 100,000 accepted HTTP(S) channels, and 10 MiB for the combined UTF-8 byte lengths of their names and resolved URLs. These are separate limits: a small input can exceed the expanded limit when relative URLs resolve against a long base URL. Generated channel names count too. A playlist exceeding any limit is rejected rather than truncated. The expansion and channel limits bound resource use from compact or malicious inputs; they do not make untrusted playlists safe.

The web API also limits the JSON request body to 64 MiB, allowing for JSON escaping of playlist contents. A browser load that fails, including due to these playlist limits, reports that the playlist could not be loaded. An explicitly supplied startup playlist fails startup if it exceeds a limit; an unusable default startup playlist leaves the web UI available for a new selection.

## Responsiveness

Playlist loading and saved-state reads run separately from request handling, so a slow playlist fetch need not block other requests. Work and response concurrency are bounded; under load the API can return HTTP 503 (server busy), so retry after other requests finish. Slow uploads can time out. If overlapping successful selections for the same browser finish out of order, an older selection cannot overwrite a newer one already saved; the superseded request receives HTTP 409. These limits improve responsiveness but do not guarantee availability under heavy load.

Only use trusted playlist sources. The local web API can fetch an operator-selected URL, including private network destinations and redirects; do not expose it as an untrusted URL-fetching service. Loopback-only binding and Host and Origin checks help restrict access; there is no authentication or TLS on the UI itself. Do not publish or reverse-proxy the UI to an untrusted network. Other local users can access it. Channel names are inserted as text, not HTML, and only HTTP(S) stream URLs are accepted. Selecting a channel contacts its server from the browser; a malicious playlist can therefore direct the browser to network destinations accessible from that browser.

HTTP Basic credentials entered in the browser are used for the playlist request, not for video playback. Use HTTPS for remote playlist URLs: HTTP Basic credentials sent over HTTP are clear text. The UI saves the source URL, username, password, uploaded file contents, and parsed channels to a per-browser server-side directory. These are stored unencrypted in owner-only directories and files; protect the host and its backups. A random HttpOnly browser cookie is the identifier, not an authenticated user account: anyone with the cookie can access its saved settings. Clearing it creates a new identity and does not remove the old data. Saved sources are not automatically refreshed. Compose retains the data in its named volume until explicitly removed. No automatic cleanup or aggregate storage quota is provided. Playlist and stream URLs can contain credentials. Playlist URL arguments (including background child arguments) and mpv stream arguments may be visible to local process inspection or shell history. Stream URLs are exposed in the local `/api/channels` response and browser developer tools, and providers receive them when played. Avoid sensitive URLs on shared systems. The list output does not display stream URLs. Error messages avoid printing HTTP request URLs.
